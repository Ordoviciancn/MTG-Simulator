# Windows 桌面版

`pnpm desktop:build` 构建客户端和服务端，输出 `release/MTG Simulator-win32-x64/MTG Simulator.exe`。这是包含 Electron/Chromium/Node 的真实 Windows 程序；分发时保留整个目录，不能单独复制 exe。构建输出不会加入 Git。`pnpm desktop:dev` 用同一打包结构启动开发桌面窗口。

启动后选择“连接远程服务器”，在大厅填写同一服务器地址即可创建、查找和加入房间。远程玩家无需安装 Forge、JDK 或 Node。软件没有预设已上线的公共服务器。卡图通过 Scryfall 在线加载。

选择“本机主持对局”时，需要已运行 `scripts/构建Forge核心.ps1` 的项目根目录、JDK 17 或更高版本，以及用于校验 Forge 固定提交的 Git。规则运行库未捆绑在客户端中；全卡池机制尚未逐项验收。

配置保存在 Electron 用户数据目录的 `runtime.json`，可通过菜单“对局 → 运行环境位置”查看。设置 `FORGE_WORKSPACE_ROOT` 和 `JAVA_HOME` 可覆盖路径。运行环境需保持可写，因为目前每局 Forge 的隔离用户目录创建在该项目 `.local-tools` 下。移动项目后重新选择目录；更新源码桥接代码会影响之后新建的对局。

程序默认分配独立端口，关闭时终止自己启动的服务。远程客户端的资源服务仅监听本机；主持模式监听所有 IPv4 接口，“对局 → 服务器连接地址”显示局域网地址。主持者退出会丢失其内存中的对局；Java 崩溃恢复和断点续局尚未完成。“对局 → 新窗口”可供第二位本机玩家连接同一服务器。公网部署及专用服务器运行方式见 `docs/联机部署与玩家分发.md`。

大厅支持编辑主牌与备牌、导入牌表、保存多套牌组和导出备份。桌面牌组写入用户数据目录 `deck-library.json`，不依赖每次启动分配的端口。牌组不会自动同步至服务器。

渲染窗口开启沙箱、上下文隔离并关闭 Node 集成；不允许新窗口打开外部网页或取得设备权限。全屏切换使用 F11 或“视图 → 全屏”。当前产物未签名，尚非安装器或正式发行版。

自动化启动检查可设置 `MTG_DESKTOP_SMOKE` 为输出 JSON 的绝对文件路径；程序验证 `/health`、页面加载并退出。`MTG_REMOTE_CLIENT=1` 跳过模式选择，配合 `MTG_TEST_PROFILE` 指定隔离用户目录时还验证原生牌组读写；不要将测试目录指向真实用户数据。这不替代 Forge 对局测试。
