# MTG Tabletop 介绍视频自动录制工具设计

## 目标

制作一个可一次性运行、全程自动演示 MTG Tabletop 功能的本地录制工具。工具驱动两个真实浏览器玩家完成示例对战，录制画面保持单一牌手视角，并加入我方虚拟光标、点击反馈和字幕。

这不是正式产品功能。工具不得向正常应用增加 `/demo` 路由、演示状态或线上功能；视频制作结束后，删除独立目录即可完整移除。

## 交付边界

所有录制相关文件放在独立目录：

```text
video-demo/
├─ start-demo.cmd
├─ run-demo.mjs
├─ cursor-overlay.js
├─ subtitle-overlay.js
├─ scenario.mjs
├─ decks/
└─ assets/
```

- 不修改 `src/client`、`src/server` 或 `src/shared` 的正式业务逻辑。
- 不改变正常构建入口、WebSocket 协议或房间状态。
- 不把录制工具加入生产构建。
- 不写入真实玩家现有的浏览器资料；自动化使用独立临时浏览器上下文。
- 删除 `video-demo` 后，项目回到没有录制工具的状态。

## 运行方式

用户双击 `video-demo/start-demo.cmd`。脚本检查环境，构建并启动本地服务，创建两个隔离浏览器上下文，等待资源加载，自动进入录制画面并播放全部章节。结束后停留在项目地址和免责声明画面，等待用户停止录屏。

工具不编码或导出 MP4。用户使用 OBS、系统录屏或其他软件捕获我方浏览器窗口。

## 真实双客户端模型

- 两个页面都运行现有正式应用。
- 我方和对手通过真实 WebSocket 创建并加入同一房间。
- 双方牌表、抽牌、移动、堆叠和区域操作通过实际 UI 完成。
- 我方窗口是唯一录制画面。
- 对手窗口在后台运行，操作通过现有同步机制出现在我方画面。
- 对手手牌遵守真实隐藏信息规则；从手牌施放后，牌才在公共区域公开。

## 自动化结构

`run-demo.mjs` 使用 Playwright 控制两个浏览器页面。操作优先走真实用户路径：点击、输入、拖拽、右键、弹窗操作、阶段推进和回合切换。

`scenario.mjs` 保存有序章节与动作。每个动作包含操作者、页面、目标选择器、操作参数、字幕、等待时间和我方光标反馈。

选择器使用当前稳定的 class、表单标签和可见文字。由于工具只为本次录制服务，不向正式 UI 增加永久演示属性。

固定牌表、玩家名和操作顺序保证演示结果一致。若洗牌引入随机性，场景不依赖具体起手；需要指定牌时，通过现有找牌功能取得目标牌。

## 单一牌手视角

- 下方显示我方完整手牌和私密弹窗。
- 上方显示对手公开区域和隐藏手牌数量。
- 只有我方操作显示虚拟光标。
- 对手操作不显示光标；字幕使用“对手：……”并短暂高亮其公开区域。
- 对手私密操作不在我方画面展开。

## 虚拟光标

`cursor-overlay.js` 只在录制页面动态注入，不修改 React 源码。

- 青绿色高对比光标，旁边显示“我方”。
- 使用 CSS transform 在目标之间平滑移动。
- 左键点击显示单层扩散圆环。
- 右键横置显示双层圆环和短暂“横置”提示。
- 拖拽时切换抓取状态并平滑移动至落点。
- 输入时先移动到输入框，再逐字填写。
- 系统真实鼠标隐藏或移出录制区域，避免出现两个光标。

光标只承担视觉说明；真实操作仍由 Playwright 在 DOM 元素上执行。

## 字幕

`subtitle-overlay.js` 动态注入底部字幕层。字幕分为我方、对手和系统说明三类，每次只显示当前动作，完成后淡出。字幕只描述桌面动作，不宣称程序会自动判断费用、优先权、合法目标或裁定。

## 演示章节

目标总时长约 8 分钟，允许按实际录屏节奏调整 10%。

1. 开场（20 秒）：真实牌桌全景、项目名称与定位。
2. 准备对局（50 秒）：导入牌表、获取卡图、创建房间、对手加入。
3. 起手流程（40 秒）：洗牌、抓七与调度。
4. 基础对局（90 秒）：出地、阶段推进、横置、Cast、堆叠与结算。
5. 响应与堆叠（60 秒）：对手响应、后进先出、实体牌进入坟场。
6. 战场操作（60 秒）：Token、+1/+1 指示物、通用计数器、横置和依附。
7. 复杂区域（70 秒）：坟场、放逐、看顶、单选、多选、回顶、回底、盖放和送坟。
8. 隐藏信息（45 秒）：手牌盖放、看顶与私密记录。
9. 自动回合模式（35 秒）：常用大阶段、自动抽牌与重置。
10. 换备与断线重连（50 秒）：换备、关闭并恢复对手页面，确认进度保留。
11. 结束（20 秒）：GitHub 地址、项目边界与非官方免责声明。

## 自动播放与故障处理

- 启动后只有一次开始倒计时，全程不需要人工推进。
- 每个关键动作等待目标元素出现并确认结果后再继续。
- 单步超时后停止演示，保留窗口，并输出章节、动作和选择器。
- 卡图加载失败时允许使用文字牌，但开始前明确提示资源缺失。
- 对手重连使用现有重连机制，不伪造恢复结果。
- 结束后不自动关闭窗口，便于完成录屏收尾。

## 性能与录制规格

- 我方窗口固定为 1920×1080。
- 对手窗口可以后台运行，但不能被冻结。
- 光标与字幕只使用 transform 和 opacity，避免布局重排。
- 开始前预加载所需卡图和牌背。
- 录制不依赖 Cloudflare Tunnel 或公网对手。

## 验证标准

1. 双击脚本后能自动启动服务和两个浏览器玩家。
2. 两个玩家通过真实房间和 WebSocket 同步。
3. 从倒计时到收尾全程不需要人工操作。
4. 我方光标与点击、右键、拖拽和输入同步。
5. 对手没有光标，隐藏手牌始终不可见。
6. 所有章节依序完成；失败时能准确停止并报告动作。
7. 1920×1080 画面无关键内容遮挡或裁切。
8. 正常应用构建和对局行为没有变化。
9. 删除 `video-demo` 后不留下产品代码、入口或配置依赖。

## 不在本阶段实现

- 把自动演示发布到线上。
- 修改正式产品以支持演示模式。
- 自动输出 MP4 或自动控制 OBS。
- 双视角或对手光标。
- 用户可编辑的通用回放系统。
- 长期维护的端到端测试框架。
