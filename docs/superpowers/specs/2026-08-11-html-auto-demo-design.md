# MTG Tabletop HTML 自动演示设计

## 目标

为 MTG Tabletop 增加一个可重复播放的浏览器演示入口，用单一牌手视角自动展示双方示例对战和主要功能，供录屏制作约 8 分钟的产品视频。

演示必须复用正式牌桌 UI、卡牌样式和区域布局，不制作与主程序分离的仿制页面。每次播放使用固定数据和固定时间轴，确保录制结果稳定一致。

## 入口与边界

- 演示入口为 `/demo`。
- 正常入口、真实房间和 WebSocket 协议不因演示模式改变行为。
- 演示状态完全保存在浏览器内存中，不创建服务端房间，不写入最近房间、玩家牌表或对局记录。
- 刷新或退出 `/demo` 后，演示状态立即丢弃。
- 演示模式使用中文界面和单一牌手视角。

## 观看视角

- 下方为我方区域，展示完整手牌与可见的私密操作。
- 上方为对手区域，对手手牌只显示数量和牌背。
- 对手从手牌施放牌时，牌在进入堆叠后才公开。
- 看顶、换备、盖放等隐藏信息只在我方操作时展示。
- 对手操作不显示虚拟光标，通过卡牌动画、对手区域轻微高亮和简短字幕表达。

## 技术结构

### 演示入口

客户端入口根据 `window.location.pathname` 选择正常应用或演示应用。`/demo` 渲染 `DemoApp`，其余路径继续渲染现有 `App`。

### 演示状态

演示使用独立的 `DemoState`，字段与牌桌渲染所需的 `ClientRoomView` 保持兼容，并增加当前章节、逻辑时间、播放状态、字幕、我方虚拟光标和目标反馈。

演示使用固定牌表、固定卡牌 ID、固定卡图映射和固定起手，不调用随机洗牌。卡图加载失败时仍能退化为现有文字牌。

### 时间轴引擎

时间轴由有序步骤组成。每个步骤包含章节、计划开始时间、持续时间、操作者、字幕、可选光标移动、状态变更和视觉反馈。

播放引擎使用统一逻辑时钟。暂停停止逻辑时钟；倍速只改变时钟速率；章节跳转先恢复章节快照再继续，避免快速补跑导致卡顿或状态偏差。

### 组件复用

从现有 `App.tsx` 中抽取演示需要的纯展示组件与共用类型，包括牌面、战场、堆叠、阶段中心、公共区域和相关弹窗。正常应用负责 WebSocket 与用户输入，演示应用只负责脚本驱动。

抽取范围以减少重复为限，不在本任务中全面重构现有应用。

## 虚拟光标

演示只显示一个我方虚拟光标。

- 使用青绿色高对比样式，并标记“我方”。
- 光标在目标之间平滑移动。
- 左键点击显示单层扩散圆环。
- 右键横置显示双层圆环和短暂“横置”反馈。
- 拖拽时切换抓取状态，目标牌抬起并跟随移动，落点显示反馈。
- 输入牌表、生命值或 Token 名称时，先聚焦输入框，再逐字显示。
- 暂停、倍速和章节跳转同步影响光标、字幕与卡牌动画。
- 录制模式隐藏系统鼠标和控制栏，只保留虚拟光标。

对手不显示光标。对手行动前，其公开区域出现轻微高亮；字幕使用“对手：……”格式。

## 演示章节

总时长目标约 8 分钟，允许实现后根据动画节奏调整 10%。

1. 开场（20 秒）：牌桌全景、项目名称和定位。
2. 准备对局（50 秒）：牌表导入、Scryfall 卡图、创建房间、对手加入。
3. 起手流程（40 秒）：自动洗牌、抓七和调度。
4. 基础对局（90 秒）：出地、推进阶段、横置法术力、拖入 Cast 区、形成堆叠并结算。
5. 响应与堆叠（60 秒）：对手响应、后进先出、实体牌进入坟场。
6. 战场操作（60 秒）：Token、+1/+1 指示物、通用计数器、横置和依附。
7. 复杂区域操作（70 秒）：坟场、放逐、看顶、单选、多选、回顶、回底、盖放和送坟。
8. 隐藏信息（45 秒）：手牌盖放、看顶和私密记录。
9. 自动回合模式（35 秒）：常用大阶段、自动抽牌和重置。
10. 换备与重连（50 秒）：主牌与备牌交换、模拟断线并恢复桌面。
11. 结束（20 秒）：项目定位、GitHub 地址和非官方免责声明。

章节之间使用真实 UI 状态变化衔接，不使用独立宣传插页。标题和说明叠加在实际界面的留白区域。

## 播放控制

演示控制栏提供播放、暂停、重播、`0.5x / 1x / 1.5x / 2x` 倍速、章节跳转、字幕开关、录制模式和全屏。

控制栏固定在画面底部，尺寸稳定。录制模式下自动隐藏；鼠标移动到底部或按 `Esc` 后恢复。

## 字幕与视觉反馈

- 每次只显示当前动作，不堆积说明。
- 我方字幕使用“我方：……”；对手字幕使用“对手：……”；系统步骤使用中性描述。
- 字幕只描述实际桌面动作，不暗示自动规则裁定。
- 当前目标允许短暂聚焦描边，但不永久修改正式 UI。
- 不展示内部时间轴、调试状态或开发术语。

## 性能与可靠性

- 时间轴使用小粒度状态更新，避免高频重建整棵 UI。
- 光标移动和点击反馈使用 CSS transform、opacity 和 transition，避免布局重排。
- 章节跳转使用预计算快照，不从开头快速执行全部步骤。
- 卡图预加载完成后才启用播放，失败图片按现有文字牌降级。
- 1920×1080 为主要录制规格，同时保证 1440×900 不遮挡关键控件。

## 验证标准

1. `/demo` 可直接打开，不需要创建房间或第二名玩家。
2. 完整播放无 JavaScript 错误、卡死或状态中断。
3. 暂停、继续、倍速、章节跳转和重播后状态正确。
4. 我方虚拟光标与点击、右键、拖拽和输入同步。
5. 对手隐藏信息始终不可见。
6. 正常入口的房间、重连和对局功能不受影响。
7. 1920×1080 与 1440×900 下无关键元素重叠或裁切。
8. 录制模式隐藏系统鼠标和控制栏，字幕与虚拟光标仍显示。
9. 生产构建通过，并使用浏览器完整播放一次进行视觉检查。

## 不在本阶段实现

- 导出 MP4 或集成视频编码器。
- 用户自定义演示脚本编辑器。
- 多语言演示时间轴。
- 双视角或分屏演示。
- 真实服务端房间回放。
- 自动生成旁白音频。
